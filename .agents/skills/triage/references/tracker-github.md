# Tracker Binding: GitHub (triage)

Issues + labels; a Project (v2) supplies board/priority fields when the
pointer has `tracker.project`. Roles ARE labels on GitHub - same names as
the role tags. Match reserved labels case-insensitively.

| Triage operation | GitHub command |
|---|---|
| Query buckets | Search: untriaged `-label:triaged state:open`; `label:needs-triage`; `label:needs-info` with new reporter comments |
| Read an issue fully | MCP `get_issue` + comments, or `gh issue view N --json body,labels,comments,milestone` |
| Apply category roles | Labels `bug` / `enhancement` (GitHub has no Type field; the default `bug`/`enhancement` labels exist in most repos) |
| Apply state roles | Labels - role names are the label names (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`) |
| Mark triaged | On disposition (not `needs-info`): remove `needs-triage` label, add `triaged`. Untriaged query: `-label:triaged state:open` |
| List dimension values | `.agents/config/dimensions.md` (generated by gh-pull: project Status/Priority/etc fields + repo labels); else `gh label list` + project fields in the UI |
| Group work by topic | The project's own groupings are `topic:<tag>` labels, listed under **Topical labels** in `.agents/config/dimensions.md`. Reuse one before adding. To add: append a line to `.agents/config/topical-tags.md` (the agents' list - it is committed and reviewed), then `story-reconcile/scripts/gh-pull.sh --dimensions-only --push-tags` creates the label. Nothing constrains what a tag looks like; name it so it groups the work usefully. GitHub has one label set for everything, so the `topic:` prefix is the only thing keeping these apart from workflow labels - never drop it. |
| Set priority | Projects mode: the project's Priority field. Issues-only: `priority:<level>` label (create deliberately, reuse existing) |
| Subsystem | No field on GitHub - use a `subsystem:<name>` label ONLY if the project adopts that convention; otherwise note in body |
| Set release | Milestone (`gh issue edit N --milestone "1.2"`) - never a label |
| Link related issues | Body/comment references, most specific phrasing: `Duplicate of #N` (then close as not planned), `Depends on #N`, `Part of #N`, `Discovered from #N`. GitHub auto-links; "Duplicate of" is recognized natively |
| Post triage notes / briefs | `add_issue_comment` / `gh issue comment` |
| Put AC into the description | Read-modify-write the body (canonical `## Acceptance Criteria` task list); fetch fresh immediately before writing |
| Close (wontfix) | Close as "not planned" - never delete |

The installer pre-creates the reserved label set. Labels a human added are
data - never remove or rename on your own initiative; propose, execute
only what they approve. Topical labels: Title Case, reuse before
inventing.
